# 视频工具箱（vtoolbox）· 飞牛 fnOS 应用

批量删除视频片头/片尾、批量合并视频的飞牛 NAS 应用，打包为可直接手动安装的 `.fpk`。

- **删除片头 / 片尾**：可选「只删片头 / 只删片尾 / 片头片尾都删」，时长自定义（支持 `90`、`1:30`、`00:01:30` 三种写法），默认「精准」模式，切点精确到帧。
- **合并视频**：参数一致时秒级直拼；可选**分组方式**——按参数、按分辨率或按横竖屏，各组分别合并为独立视频，或改用「标准合并」统一分辨率/帧率后重新编码。
- **合并后收尾源视频**：合并完成后可自动把「参与合并的源视频」**移动**到它们各自目录下的「已合并视频」子文件夹归档，或直接**删除**；默认保留不动。
- **多目录切换**：授权多个文件夹后，列表上方「授权目录」一栏可随时切换。
- **列表排序**：点表头的「名称 / 时长 / 大小」即可排序，再点一次切换升降序；目录始终置顶。
- **封面分组**：按视频封面（首帧）指纹分组，一眼找出/一键选中封面相同的视频。
- **核显加速**：Intel/AMD 核显可用时自动启用硬件编码，失败自动回退软件编码。
- **输出位置默认值**：可在设置里把「当前所在目录」设为默认，之后切到哪个目录就输出到哪。
- **安全**：默认只读源文件，所有结果输出到指定目录，不覆盖原片；任务可随时取消。

## 一、安装

1. 打开飞牛桌面「应用中心」→ 右上角「设置」→「手动安装应用」。
2. 选择 `vtoolbox-1.0.7.fpk`，按向导完成安装（可选默认切割方式、并发数、同名处理策略、是否开启核显加速）。
3. 安装后桌面出现「视频工具箱」图标，点击即可打开 Web 控制台。

> 也可以在 SSH 中安装：`trim-cli app install-fpk vtoolbox-1.0.7.fpk --volume-id 1 --yes`

### 两个包的区别

| 包 | 说明 |
|---|---|
| `vtoolbox-1.0.7.fpk` | 默认包。`config/privilege` 声明了 `join-groups: ["video","render"]`，用于访问 `/dev/dri` 开启核显加速 |
| `vtoolbox-1.0.7-cpu.fpk` | 降级包。不含 `join-groups`，仅软件编码。**万一默认包因系统缺少 video/render 组装不上，就用这个** |

### 安装失败怎么排查

| 报错 | 原因与处理 |
|---|---|
| 应用文件不完整：缺少内置 ffmpeg | 1.0.1 已修复（原因为校验时机错误）。若仍出现，说明包内 `bin/ffmpeg` 缺失，请重新下载安装包 |
| 应用文件不完整：缺少 server/main.py | 安装包下载不完整，重新下载 |
| 系统缺少 python3 | fnOS 自带 `/usr/bin/python3`；如被移除请先恢复系统环境 |
| 安装空间不足 | 包内自带静态 ffmpeg/ffprobe（解压后约 152MB），请留出至少 512MB 可用空间 |
| 报错提到用户组 / group | 系统缺少 `video` 或 `render` 组，改用 `vtoolbox-1.0.7-cpu.fpk` 重装 |

安装过程与结果会记录到 `${TRIM_PKGVAR}/install.log`（通常为 `/vol{n}/@appdata/vtoolbox/install.log`），里面有运行用户、`/dev/dri` 权限、硬件加速开关等排障信息。

应用自带静态 ffmpeg；若包内二进制意外缺失，会自动回退使用系统 ffmpeg（`/usr/trim/lib/mediasrv/ffmpeg` 或 `/usr/bin/ffmpeg`），此时界面右上角会显示「ffmpeg …（系统）」。

## 二、首次使用必做：授权目录

应用遵循飞牛的最小权限模型，**默认看不到你的任何文件**。请先授权：

1. 应用中心 → 「视频工具箱」→「应用设置」→「授权目录」。
2. 把存放视频的目录（例如 `/vol1/media`）授予本应用，保存。
3. 重新打开「视频工具箱」，左侧即可浏览该目录。

**授权了多个目录**时，视频列表上方会出现「授权目录」切换栏，点一下即在该目录间跳转（会记住上次用的目录）。

输出目录同样需要在授权范围内。安装时应用会创建共享目录 `vtoolbox/output`，它会自动出现在授权列表中，可作为默认输出位置。

## 三、使用步骤

1. **选片**：在左侧进入目录 → 勾选视频（可「全选本页」）；需要批量处理子目录时点「递归扫描」。
   多个授权目录用上方切换栏切换；「↑ 上级」到授权目录顶层会自动置灰。
2. **选模式**：右上角切换「删除片头」或「合并视频」。
   - 删除片头：填时长、选切割方式、设文件名后缀。
   - 合并视频：在右侧「合并顺序」中确认顺序（支持按文件名排序 / 反转）；选「分组方式」；
     点「分析参数分组」可先看当前分组方式下会怎么分组；
     再选「合并后处理源视频」——默认保留不动，可改为移动到「已合并视频」文件夹或删除。
3. **设输出**：「用当前目录」或「用默认目录」，也可直接填路径；选择输出格式与同名处理策略。
4. **开始处理**，切到「任务」标签查看实时进度、速度与完整日志。

### 合并方式怎么选

| 方式 | 行为 |
|---|---|
| 自动 | 参数一致就直接拼接；不一致就统一分辨率/帧率重新编码成一个视频 |
| 直接拼接 | 参数一致时秒级直拼；**参数不一致时按所选分组方式分组，每组各自拼接成一个视频**，输出 `名称_1`、`名称_2`…（只有一个文件的组会跳过并说明） |
| 标准合并 | 不管参数是否一致，统一到最大分辨率/最高帧率重编码成一个视频 |

### 分组方式怎么选（合并视频）

「分组方式」决定了哪些文件会被归到同一组、合并进同一个成品：

| 分组方式 | 归组规则 | 适用场景 |
|---|---|---|
| 按参数（默认） | 编码格式、分辨率、帧率、像素格式、音轨参数**全部一致**才同组 | 想要同源素材秒级直拼、不同参数分开处理 |
| 按分辨率 | 画面像素尺寸（宽×高）**相同**即同组，忽略编码/帧率差异 | 同一批不同清晰度的素材，按清晰度分开成片（1080p 一组成一个、720p 一组成一个） |
| 按横竖屏 | 横屏视频只与横屏合并、竖屏只与竖屏合并；宽高比接近 1:1 的单独成组 | 手机竖拍与横拍素材混在一起，分别合并、互不掺混 |

- 「按分辨率」与「按横竖屏」在**标准合并**下会先分组、再在组内统一参数重新编码；
  这样同分辨率但编码/帧率不同的文件也能真正合成一个画面。
- 选「按横竖屏」时可调**比例容差**（默认 5%）：
  `|宽/高 − 1| ≤ 容差` 的视频被视作近似方形、单独成组，不并入横屏或竖屏组。
  容差越大，越多的方正画面会被单独拆出。
- 点「分析参数分组」（会按当前分组方式分析）可预览归组结果；
  每个分组只有 1 个文件的组会被跳过。

想按片源分成几个文件，就用「直接拼接」或「按分辨率/横竖屏分组」；想合成一个文件，用「自动」或「标准合并」。

### 合并完成后怎么处置源视频

合并面板里有「合并后处理源视频」一项，三个选择：

| 选择 | 行为 |
|---|---|
| 保留不动（默认） | 源视频一个字都不动 |
| 移动到「已合并视频」文件夹 | 把参与合并的源视频，移动到自己**各自所在目录**下的 `已合并视频` 子文件夹里归档 |
| 删除源视频 | 永久删除参与合并的源视频（**不可恢复，选它时会二次确认**） |

**只有「真正被合并」的文件才会被处理。** 具体规则：

- 「直接拼接」遇到参数不一致时会按参数分组——如果某个组只有 1 个文件，该组会被跳过、**根本不会产出成品**，
  因此它的源文件**既不会被移动也不会被删除**（否则会出现"文件没了但什么都没合并出来"）。
- 同理，只选了 1 个文件时不算合并，源文件原样保留。
- 失败的分组不会处理其源文件。

归档时的安全细节：

- 目标文件夹里已有同名文件时**自动改名**（追加 ` (1)`、` (2)`…），绝不覆盖。
- 源文件本来就在 `已合并视频` 文件夹里时直接跳过，避免嵌套出 `已合并视频/已合并视频`。
- 移动用 `rename` 语义（同盘几乎瞬间完成），逐个容错——个别文件失败不影响其余文件，也不影响已生成的成品。

> 合并面板点「分析参数分组」后，被跳过的单文件组会标注「仅 1 个文件，无法合并」，
> 选了移动/删除时还会补一句"也不会被移动/删除"，提交前就能核对清楚。

### 按封面分组找相同封面的视频

点工具栏「按封面分组」：应用提取每个视频的封面帧（首帧），算 64 位感知哈希后聚类，把封面一致的视频归到一组。

- 同一图案/同一片源的不同编码、不同分辨率也能认出来（哈希与分辨率无关）。
- 每组左侧显示缩略图，右侧「选中该组」一键勾选整组；勾「只看封面相同的分组」可过滤掉只有一个视频的组。
- 结果缓存到 `${TRIM_PKGVAR}/cover-cache.json`，第二次分析几乎秒出。
- 一次最多分析 600 个文件，本机 4 路并行提取。

### 核显硬件加速

设置页（或安装向导）把「核显硬件加速」设为「自动」即可。要点：

| 事项 | 说明 |
|---|---|
| 为什么用系统 ffmpeg | 包内自带的静态 ffmpeg **不含** VAAPI/QSV，硬件加速会改用系统 ffmpeg（`/usr/trim/lib/mediasrv/ffmpeg` 或 `/usr/bin/ffmpeg`） |
| 权限 | 应用已声明 `join-groups: ["video","render"]` 以访问 `/dev/dri`；装上后若显示不可用，看安装日志里的「核显设备」一行 |
| 生效范围 | 只作用于**标准合并**与**整片重编码**。精准切割的片头段仍用软件编码（要保证能与后段直接拼接） |
| 失败处理 | 启动前真实试编一帧，能跑才用；运行中万一失败会自动回退软件编码重试，任务不会因此失败 |
| 质量参数 | VAAPI 用 `-rc_mode CQP -qp <crf>`；QSV 用 `-global_quality <crf> -preset <preset>` |

设置页「运行环境」会显示当前用的是内置还是系统 ffmpeg、核显是否可用、以及不可用的原因。

## 四、公网 / 域名访问

桌面入口使用飞牛的**统一网关**（`app/ui/config` 中的 `gatewaySocket` + `gatewayPrefix`）：
服务启动时在包内目录创建一个 Unix Socket，飞牛校验登录态后把 `/app/vtoolbox/...` 的请求转发进来。
这样应用**复用飞牛当前的域名与协议**，所以不管你是从局域网 IP、公网 IP 还是域名访问飞牛，桌面上打开本应用都能正常显示，也**不需要额外对外开放 5230 端口**。

> **⚠️ 入口配置里千万不要声明 `port` / `protocol`。**
> 一旦声明了端口，飞牛桌面就会按「协议 + 端口」去拼 iframe 地址（形如 `https://<你的地址>:5230/`）。
> 在 HTTPS 页面下这必然失败：走 https 而该端口没有 TLS 握手，走 http 又被浏览器按「混合内容」拦掉 ——
> 两种结果都是**一片空白**，而且页面里看不到任何来自应用自身的报错。**1.0.4 起已移除端口声明**，强制同源网关加载。

前端资源与接口都使用相对路径，因此以下两种地址都能正常打开：

| 访问方式 | 地址 |
|---|---|
| 桌面图标（推荐） | `http(s)://<你访问飞牛的地址>/app/vtoolbox` |
| 局域网直连（备用） | `http://<内网IP>:5230/` |

### 白屏 / 打不开怎么排查

服务端会逐条记录访问日志（`${TRIM_PKGVAR}/server.log`），并标注请求来源：

```
访问[网关] GET /app/vtoolbox/ -> 200
访问[直连] GET /api/state -> 200
```

| 现象 | 原因与处理 |
|---|---|
| 日志里**完全没有**「访问[网关]」 | 桌面没把请求送到应用。确认已升级到 **1.0.4 及以上**（该版本移除了入口端口声明），并在飞牛桌面**重新打开**一次（必要时退出登录再进，避免桌面缓存旧入口配置） |
| 有「访问[网关]」但页面仍白 | 静态资源没跟着前缀走，检查 `app/ui/config` 的 `url` 是否为 `/app/vtoolbox` |
| 启动日志出现「无法创建网关 socket」 | 应用目录对运行用户不可写。`install.log` 里会记录「网关 socket 目录」是否可写 |
| 想确认网关是否已启用 | 启动日志出现 `网关 socket：.../vtoolbox.sock（/app/vtoolbox）` 即已启用 |
| 网关不可用时的兜底 | 应用仍监听 5230，可把 `http://<内网IP>:5230/` 填进浏览器地址栏直接使用（注意：HTTPS 的飞牛页面里嵌这个地址会被浏览器拦截，必须**新开标签页**访问） |

## 五、切割方式与「精准」模式怎么工作

| 模式 | 原理 | 速度 | 精度 |
| --- | --- | --- | --- |
| 精准（默认） | 在切点附近找到关键帧：片头侧取切点后第一个关键帧、片尾侧取切点前最后一个关键帧，**只重编码夹缝里那一小段**（通常 1–3 秒），中间的整段直接复制，最后拼接 | 接近秒级 | 精确到帧，不残留 |
| 快速 | `-ss 切点 -c copy` 纯复制 | 秒级 | 切点会对齐到关键帧，开头/结尾可能多出数秒画面 |

只删片头是「重编码开头一小段 + 复制到尾」；只删片尾是「复制到倒数第二个关键帧 + 重编码尾巴一小段」；两头都删则中间整段仍原样复制。**无论删哪一端，都只重编码切点附近几秒。**

源片编码不是 H.264/HEVC（或为 10bit H.264）时无法两段式切割，会自动回退为整片重新编码，速度较慢但结果准确，日志中会说明原因。

### 勾选很多视频时「读取视频信息失败 / 502」是怎么回事

探测时长需要逐个调用 ffprobe，而飞牛网关（nginx）默认 60 秒读超时。旧版把整批文件塞进一个请求，文件一多必然超时。现在改成三层防护：

1. 前端**小批（10 个）串行**发送，不并发压垮后端；
2. 单批失败时**自动拆成两半各重试一次**，不会整批作废；
3. 后端用**线程池并发**执行 ffprobe，并把单次上限收窄到 200 个。

如果仍然出现 502，可在 `${TRIM_PKGVAR}/server.log` 里搜 `访问[网关]` 看请求是否真的到达了应用。

## 六、目录结构

```
videotoolbox/
├── manifest                 应用元信息（appname / 版本 / 端口 5230 / 架构 x86）
├── ICON.PNG, ICON_256.PNG   应用图标
├── config/
│   ├── privilege            运行身份（run-as: package + join-groups: video/render 用于核显）
│   └── resource             数据共享目录声明
├── wizard/
│   ├── install              安装向导
│   └── config               应用设置向导
├── cmd/                     生命周期脚本（main / install_* / upgrade_* / uninstall_* / config_*）
│                            注意：install_init 在「文件落盘前」执行，只能做环境类检查；
│                            包内文件完整性校验必须放在 install_callback（文件落盘后）
├── app/
│   ├── server/              后端（Python 3 标准库：main.py / media.py / jobs.py）
│   ├── www/                 Web 控制台（index.html / style.css / app.js）
│   ├── bin/                 内置静态 ffmpeg + ffprobe（构建时下载）
│   └── ui/                  飞牛桌面入口配置与图标（config 声明统一网关 gatewaySocket/gatewayPrefix）
├── build/
│   ├── gen_icons.py         图标生成（无第三方依赖）
│   └── cache/               下载缓存
├── tests/                   e2e.py（处理逻辑）+ gateway_check.py（网关入口）+ verify_fpk.py（打包与生命周期）
└── build.sh                 一键构建
```

运行期数据位置（由飞牛托管，升级不丢失）：

- 配置：`/vol{n}/@appconf/vtoolbox/config.json`
- 任务记录与日志：`/vol{n}/@appdata/vtoolbox/jobs.json`

## 七、从源码构建

```bash
bash build.sh                    # 下载静态 ffmpeg + 生成图标 + 打包
bash build.sh --skip-ffmpeg      # 已有 app/bin/ffmpeg 时跳过下载
bash build.sh --cpu-variant      # 额外产出不含 join-groups 的降级包
```

产物在 `dist/` 下。首次构建需要下载约 40MB 的静态 ffmpeg。

## 八、本地测试

```bash
python3 tests/e2e.py --ffmpeg /usr/bin/ffmpeg --ffprobe /usr/bin/ffprobe
python3 tests/gateway_check.py  # 网关入口：TCP 直连 / 带前缀 / Unix Socket 三种访问方式
python3 tests/verify_fpk.py    # 解包 dist/ 下的 fpk，模拟飞牛安装布局与生命周期
```

`e2e.py` 会生成多组测试视频，覆盖：精准切割的首帧一致性、只删片尾与片头片尾都删、快速模式行为、同源拼接与异构合并的时长与分辨率、按封面分组（跨编码/跨分辨率识别同封面）、缩略图接口、参数分组预览、直接拼接的分组合并、**合并后源视频的移动/删除与「单独成组不受影响」**、**按分辨率分组、按横竖屏分组（含比例容差边界与方形单独成组）**、批量探测与默认输出位置，以及未授权路径、超长片头、单文件合并、非法分组参数回落等边界；另外还有一组不依赖真实 GPU 的单元校验（VAAPI/QSV 参数拼装、封面聚类阈值）。

`verify_fpk.py` 按官方语义模拟安装时序：**先**在空的 `target/` 上跑 `install_init`（回归点：不得误报文件不完整），**再**解包 `app.tgz`、跑 `install_callback`，然后 `main start/status/stop`、跑真实任务、重启验证持久化，并覆盖「内置 ffmpeg 缺失时回退系统 ffmpeg」这一兜底路径；此外还校验 `app/ui/config` 的统一网关声明、启动后是否真的创建了 `vtoolbox.sock`，以及经该 socket 访问 `/app/vtoolbox/api/state` 是否正常。

## 九、已知限制

1. 精准模式仅支持 H.264 / HEVC 源片，其他编码回退整片重编码。
2. 合并与切割默认只保留**第一条视频流 + 全部音轨**，会丢弃字幕流与封面图；需要保留字幕请改用「快速」模式或重新封装。
3. 服务同时监听 5230 端口（与 `manifest` 的 `service_port` 一致）与包内 `vtoolbox.sock`（供飞牛统一网关转发）。桌面图标走网关，端口只作为局域网直连的备用入口。
   临时排障可用环境变量覆盖端口：`VTOOLBOX_PORT=5300 bash cmd/main start`（仅改监听端口；长期改端口需同步改 `manifest` 与 `app/ui/config` 后重新打包）。
   另：`VTOOLBOX_DRY_RUN=1 bash cmd/main start` 只打印将要执行的启动命令行、不真正启动，便于排障。
4. 核显加速仅作用于**标准合并**与**整片重编码**；精准切割的片头段为保证能与后段无缝拼接，仍使用软件编码。
5. 核显加速依赖系统 ffmpeg 的 VAAPI/QSV 支持与 `/dev/dri` 访问权限。部分机型核显驱动不可用（日志会显示原因），此时自动回退软件编码，功能不受影响。
6. 封面分组一次最多分析 600 个文件；封面完全为黑帧或纯色时哈希相近，可能被并为一组（已按「首帧」取样，必要时可调大取样时间点）。
7. 「按分辨率」「按横竖屏」分组会输出**多个**成品（每组一个），组内若有参数（编码/帧率）差异会统一重编码；只含 1 个文件的组会跳过、不产出成品，其源文件在「合并后处理源视频」中也不会被移动或删除。
8. 横竖屏判定用的是显示的宽高像素比；旋转元数据（rotate tag）未做额外归一，个别竖拍但带旋转标记的片源可能被按存储尺寸判定，必要时可在系统里先转码修正。
7. 仅提供 x86_64 包（`platform=x86`）。ARM 机型需用 arm64 版静态 ffmpeg 重新构建并把 `platform` 改为 `arm`。
8. 「合并后处理源视频」中的**删除**是永久删除，不进回收站，也不校验成品能否正常播放；建议先用「移动」跑一轮，
   确认成品没问题后再改用「删除」。移动只在源文件自己所在目录内新建 `已合并视频` 子文件夹，因此总是同盘改名，不会真的搬运数据。
9. 源视频与目标文件夹必须对运行用户可写；否则该文件会被跳过并记进任务日志，其余文件与已生成的成品不受影响。
